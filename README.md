# Differentially Private Federated Graph Learning for Cross-Institutional AML

Code for an empirical study of the **privacy-utility trade-off of client-level differentially private (DP) federated graph learning** for transaction-level money-laundering detection across institutions.

Ten simulated banks each hold only their own transactions. A GraphSAGE edge classifier is trained with DP-FedAvg (per-client clipping, server-side Gaussian noise, Rényi-DP accounting) and compared with centralized, federated, and tabular baselines on the IBM AMLworld HI-Small benchmark.

> **Headline finding.** On this benchmark, no configuration with a meaningful privacy budget beat chance in ROC-AUC, and a plain gradient-boosted tabular model outperformed every graph model. The repository is a reproducible record of that negative result and the controls that explain it.

## What this repository does

1. **Builds a transaction graph** from AMLworld HI-Small: accounts are nodes, transactions are directed edges with 15 edge features; 14 node features are computed from training-split edges only.
2. **Splits temporally** (60/20/20 train/validation/test) so the model is always evaluated on later transactions.
3. **Partitions edges across ten bank clients** (the ten largest banks by volume), so each client only ever sees its own records.
4. **Trains** logistic regression, HistGradientBoosting, centralized GraphSAGE, federated GraphSAGE, and DP-federated GraphSAGE.
5. **Evaluates** with ROC-AUC and with precision and recall inside fixed review budgets (top 1%, 5% and 10% of transactions), which is how an investigator would actually use a ranked alert list.
6. **Runs controls** that separate the cost of federation from the cost of reduced model capacity and reduced data coverage, and measures how much noise the DP mechanism injects relative to the client updates.

## Results at a glance

Test split, 1,015,669 transactions, 1,798 positives (0.177%). Mean ± SD over seeds where stated.

| Model | Test ROC-AUC | Seeds |
|---|---|---|
| Logistic regression | 0.638 | 1 (deterministic) |
| HistGradientBoosting (tabular) | **0.850** | 1 |
| Centralized GraphSAGE | 0.689 ± 0.020 | 3 |
| Federated GraphSAGE (no DP) | 0.572 ± 0.043 | 5 |

Effect of client-level DP (uniform clipping, C = 1.0, 10 rounds, δ = 10⁻⁵):

| Noise multiplier σ | ε (RDP) | Test ROC-AUC | Seeds |
|---|---|---|---|
| 0 (no noise) | ∞ | 0.574 ± 0.059 | 5 |
| 0.05 | ≈ 2,300 | 0.563 | 1 |
| 0.5 | ≈ 50.4 | 0.437 ± 0.050 | 5 |
| 3 | ≈ 5.61 | 0.475 ± 0.049 | 5 |
| 5 | ≈ 3.23 | 0.474 ± 0.050 | 5 |

Notes:

- At σ = 0.5 the injected noise norm (about 12) exceeds the client update norm (about 0.9) by more than tenfold, which is consistent with a signal-to-noise explanation of the collapse.
- ROC-AUC below 0.5 means the scores are essentially arbitrary under heavy noise on a 0.18%-positive test set, not that the model has learned to detect laundering in reverse.
- Personalized (volume-aware) clipping raised the mean ROC-AUC slightly at σ = 0.5 (0.456 vs 0.437), but the difference is not statistically significant (4 of 5 seeds improved, p ≈ 0.17).
- Control experiments attribute the centralized-to-federated gap mainly to model capacity (≈ 0.04 ROC-AUC) and data coverage (≈ 0.05), with federation itself ≈ 0.03. None of these differences is distinguishable from seed variation.

Figures are generated by `make_figures.py` into `results/figures_eval/`.

## Setup

```bash
git clone <this-repo-url>
cd dpdp-mule-detection
python -m venv venv
# Linux/macOS: source venv/bin/activate     Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` pins the versions used in the experiments (PyTorch, PyTorch Geometric, scikit-learn, pandas, Flower). If PyTorch Geometric fails to install, follow the wheel instructions for your PyTorch and CUDA version in the PyG documentation. A CPU is sufficient; the model has about 13,250 parameters.

## Data

The experiments use the **IBM Transactions for Anti-Money Laundering (AMLworld), HI-Small** dataset (Altman et al., 2023), distributed through Kaggle. It is synthetic and contains no real customer data.

The dataset is **not included** in this repository. Download it yourself, check its license, and place the files here:

```
data/raw/HI-Small_Trans.csv
data/raw/HI-Small_Patterns.txt
```

The `data/raw/` and `data/processed/` folders are git-ignored.

## Reproducing the experiments

Run all commands from the repository root.

**1. Build the processed graph files**

```bash
python src/data/build_graph.py \
    --trans data/raw/HI-Small_Trans.csv \
    --patterns data/raw/HI-Small_Patterns.txt \
    --outdir data/processed
```

This writes the edge table and `edge_features.parquet` used by every model. `python src/data/dataset.py --help` shows how the graph object and node features are assembled from the processed files.

**2. Non-private baselines**

```bash
python src/models/tabular_baseline.py     # logistic regression, HistGradientBoosting
python src/models/gnn_baseline.py         # centralized GraphSAGE
python src/models/federated.py            # federated GraphSAGE, no DP
python src/models/pooled_control.py       # control experiments
```

Each script has its own options; run it with `--help` to see them.

**3. DP-federated runs**

```bash
python src/models/dp_federated.py \
    --noise_multiplier 0.5 --seed 42 \
    --rounds 10 --local_epochs 2 --lr 0.005 \
    --hidden_dim 64 --emb_dim 32 --max_norm 1.0 --delta 1e-5
```

To repeat a noise level over seeds (PowerShell):

```powershell
foreach ($s in 42,123,2024,7,999) { python src/models/dp_federated.py --noise_multiplier 0.5 --seed $s }
```

or in bash:

```bash
for s in 42 123 2024 7 999; do python src/models/dp_federated.py --noise_multiplier 0.5 --seed $s; done
```

**4. Collect results and make figures**

```bash
python collect_results.py
python make_figures.py
```

`collect_results.py` writes `results/summary.csv`. `make_figures.py` reads it together with `external_metrics.json` and writes the figures to `results/figures_eval/`.

## Method summary

- **Task.** Edge-level binary classification: is a given transaction part of a laundering pattern? The positive rate is about 0.10% overall.
- **Model.** A two-layer GraphSAGE encoder (14 → 64 → 32) followed by an edge MLP over the source embedding, destination embedding and the edge features. 13,250 parameters.
- **Federation.** Ten bank clients, 10 rounds, 2 local Adam steps per round, learning rate 0.005, weighted averaging.
- **Differential privacy.** Client-level DP-FedAvg. Each client update is clipped to norm C = 1.0. The server adds Gaussian noise with standard deviation σ·Δ, where Δ is the largest weighted per-client contribution. Aggregation uses a fixed, public denominator so that add/remove-one-client adjacency is well defined (as in McMahan et al., 2018). The privacy loss is tracked with a Rényi-DP accountant over 10 rounds and converted to (ε, δ) with δ = 10⁻⁵.
- **Evaluation.** Temporal split. Metrics are ROC-AUC and precision/recall at review budgets of 1%, 5% and 10% of the test transactions.

## Limitations

These are also stated in the accompanying paper and apply to anyone reusing the code.

- One synthetic dataset (AMLworld HI-Small) and ten simulated clients. Conclusions are specific to this setup.
- Node features and the port index are computed on the training graph outside the DP mechanism, so the privacy guarantee covers the model updates, not these inputs.
- At evaluation time the model uses message passing over the full pooled training graph. This is a simplification; a deployed system would only see client-local graphs.
- Several results use few seeds; the σ = 0.05 point is a single run.
- The study does not include secure aggregation, an empirical membership-inference test, or hyperparameter tuning under DP.
- The DP runs use a small update budget (2 local steps per round). More local steps cost no additional privacy but were not tested.

## Responsible use

This is research code on synthetic data. It is not a production fraud or AML system and should not be used to make decisions about real people or accounts. Any real deployment would need legal review for data protection and financial-regulation requirements.
